# LLM 모델 비교 및 선정 보고서

## 1. 과업 정의 및 비교 목적

- **과업:** SIEM/EDR 알람 및 비정형 관제 메모를 바탕으로 침해사고 초동 대응 보고서 초안을 작성한다.
- **타겟 사용자:** 야간·주말 교대 근무 중인 SOC 초동 분석가 및 차상위 보안 담당자
- **입력:** 탐지 시각, 가상 호스트명, IP, 관련 계정, 탐지 사유 등이 포함된 비정형 메모 또는 로그 요약
- **목표 출력:** 사고 개요 / 확인된 사실 / 누락·추가 확인 필요 사항 / 권고 초동 조치의 4개 항목, 각 항목 2~4줄의 개조식 보고서
- **우선순위:** 사실 정확성 > 정보 완전성 > 출력 형식 준수

동일한 정상 입력과 모호한 입력을 세 모델에 제공하여 사실 전달, 미확인 정보 처리 및 초동 대응 보고서 작성 능력을 비교하였다.

|---|---|---|---|
| 모델명 및 버전 | GPT-6.2 | Claude Sonnet 5.5 | Gemini 3 Flash |
| 요금제 | ChatGPT Plus (유료) | 무료 | 무료 |

모델 버전과 실행 시점은 사용자 테스트 기록에 기재된 값을 사용하였다. 무료 요금제 모델을 2종 포함하였다.

## 3. 공통 테스트 프롬프트

### 테스트 1 — 정상 입력

```text
너는 보안관제센터(SOC) 침해사고 대응 보고서 작성을 돕는 AI다.
아래 관제 알람 메모를 바탕으로 초동 대응 보고서 초안을 [사고 개요 / 확인된 사실 / 누락·추가 확인 필요 사항 / 권고 초동 조치] 4개 항목, 개조식으로 작성해 줘.
메모에 없는 IP, 해시값, CVE 번호, 원인은 절대 추측해서 채우지 말고 '확인 필요'로 남겨 줘.

- 탐지 시각: 2026-11-24 01:42
- 대상 자산(호스트/IP): HOST-ACC-09 / 10.10.4.21
- 관련 계정/프로세스: user_08 / winword.exe → cmd.exe → certutil.exe
- 관제 메모 원문: 회계팀 단말에서 문서 파일 실행 직후 cmd.exe가 certutil.exe를 호출해 외부 IP(198.51.100.77)에서 파일 다운로드를 시도함. EDR이 certutil.exe 프로세스를 즉시 종료해 다운로드는 실패했으나, 최초 실행된 문서 파일의 해시값과 유입 경로(이메일/메신저)는 아직 확인되지 않음.
- 보고 대상: 보안팀장 초동 보고용
```

### 테스트 2 — 모호한 입력

```text
방금 전에 사내 서버 쪽에서 좀 이상한 접속 로그가 몇 건 올라왔는데, 이것도 침해사고 초동 대응 보고서 초안으로 바로 정리해 줘.
```

테스트 1에서는 핵심 정보 보존과 초동 조치의 적절성을, 테스트 2에서는 정보 부족의 인식, 추가 정보 요청 및 기존 지시 유지 여부를 확인하였다.

## 4. 평가 기준 및 채점 방식

각 기준을 1~5점으로 평가하고 동일 가중치로 합산한다. 5점은 충실한 충족, 4점은 일부 개선 필요, 3점은 기본 충족이나 상당한 보완 필요, 2점은 주요 요구 미충족, 1점은 활용 곤란을 의미한다.

| 평가 기준 | 평가 내용 |
|---|---|
| 사실 정확성 | 입력에 포함된 시각, 호스트, IP, 계정, 프로세스 및 조치 결과의 정확한 전달 |
| 환각 방지 | 미확인 식별자 생성 및 공격 원인 단정 방지 |
| 정보 완전성 | 주요 정보 및 후속 확인 사항의 충실성 |
| 출력 형식 준수 | 지정된 4개 항목과 개조식 유지 |
| 모호한 입력 처리 | 정보 부족 인식 및 추가 정보 요청의 구체성 |
| 초동 대응 적절성 | 증거 보존, 영향 범위 조사, 격리·차단 권고의 신중성 |
| 가독성 및 간결성 | 교대 근무자가 신속하게 파악할 수 있는 구성 |
| 문맥 유지 능력 | 기존 지시 유지 및 서로 다른 사건의 정보 구분 |

### 5.1. 항목별 점수 근거

| 평가 기준 | GPT-6.2 | Claude Sonnet 5.5 | Gemini 3 Flash |
|---|---|---|---|
| 사실 정확성 | 핵심 식별 정보와 다운로드 실패 사실을 정확히 반영함(5점). | 핵심 관제 정보를 정확히 반영함(5점). | 핵심 정보는 정확하나 테스트 2에서 확인되지 않은 초동 확인 진행 상태를 기재함(4점). |
| 환각 방지 | 실제 침해 여부와 원인을 단정하지 않음(5점). | 허위 식별자는 없으나 악성 문서 기반 초기 침투 가설을 추가함(4점). | 미확인 IP, 해시값, CVE 번호와 원인을 임의로 채우지 않음(5점). |

| 출력 형식 준수 | 4개 항목을 유지했으나 별도 초동 판단 문단을 추가함(4점). | 4개 항목을 유지했으나 부가 설명과 세부 항목이 많음(4점). | 4개 항목 중심으로 개조식 보고서를 구성함(5점). |
| 모호한 입력 처리 | 정보 부족을 명시하고 로그 원문 제공을 요청함(4점). | 서버명, IP, 로그 원문, 이상 판단 근거를 구체적으로 요청함(5점). | 필요한 정보를 안내했으나 별도의 구체적인 확인 질문은 상대적으로 부족함(4점). |

| 가독성 및 간결성 | 구조가 명확하나 사고 개요와 확인된 사실 사이에 반복이 있음(4점). | 정상 입력에서 추가 확인 사항 13개, 권고 조치 9개를 제시하여 분량이 많음(3점). | 핵심 정보를 간결하게 구성함(5점). |
| 문맥 유지 능력 | 기존 지시를 유지하고 두 사건의 사실관계를 구분함(5점). | 이전 사건과의 연관성 대조를 구체적으로 제시하여 조사 범위가 확대됨. 실제 문맥 끊김이 확인된 것은 아님(4점). | 기존 지시를 유지하고 이전 사건의 식별자를 새 사건에 혼입하지 않음(5점). |

초기 공통 프롬프트에는 항목당 2~4줄이라는 조건이 명시되지 않았으므로, 해당 조건은 직접적인 지시 위반으로 채점하지 않았다. 또한 환각 방지 항목은 명시적으로 금지한 식별자 및 원인의 임의 생성 여부를 중심으로 평가하였다. 확인되지 않은 업무 진행 상태는 사실 정확성 항목에서 반영하였다.

## 6. 모델별 분석

### 6.1. GPT-6.2

- 확인된 사실과 미확인 사항을 명확히 구분하고, 다운로드 차단을 전체 침해사고 종료로 해석하지 않았다.
- 단말 격리 및 외부 IP 차단의 필요성을 검토하도록 권고하여 업무 영향도를 고려할 여지를 제공하였다.
- 모호한 입력에서도 침해사고 확정을 유보하고 로그 원문을 요청하였다.
- 다만 정보 반복과 별도 초동 판단 문단은 보고서 간결성 측면에서 개선이 필요하다.

### 6.2. Claude Sonnet 5.5

- 휘발성 증거 보존, 지속성 흔적, 중요 데이터 접근 이력 등 세부 조사 항목이 충실하였다.
- 모호한 입력에서 필요한 정보를 가장 구체적으로 요청하였다.
- 다만 보고서 분량이 많고, 악성 문서 기반 초기 침투 가설을 포함하였다. 이는 확정 사실로 제시한 것은 아니나 가설과 사실을 더욱 명확히 분리할 필요가 있다.
- 격리 및 IP 차단에 앞서 업무 영향도와 위협 여부를 검토하는 절차가 상대적으로 부족하였다.

### 6.3. Gemini 3 Flash

- 간결한 구성과 지정된 보고서 형식 준수에 강점을 보였다.
- 제공되지 않은 주요 식별 정보를 확인 필요로 처리하였다.
- 다만 모호한 입력에서 초동 확인이 진행 중이라고 표현하였고, 확인된 사실 항목에 프롬프트 준수에 관한 설명을 포함하였다.
- 정상 입력에서 계정 이상 인증 점검 및 IP 차단 필요성 평가가 상대적으로 부족하였다.

## 7. 최종 모델 선정

**선정 모델(검토안): GPT-6.2**

본 과업에서는 보고서의 분량이나 표현상의 완성도보다 사실 정확성, 미확인 정보의 구분 및 초동 대응의 적절성이 중요하다. GPT-6.2는 두 테스트에서 확인된 사실과 추가 확인 사항을 구분하고 공격 원인 및 실제 침해 여부를 단정하지 않았다. 또한 업무에 영향을 줄 수 있는 단말 격리 및 IP 차단에 대해 필요성을 먼저 평가하도록 권고하였다.

Claude는 상세한 후속 조사 항목과 구체적인 추가 정보 요청에서 강점을 보였으나 초동 보고서로는 분량이 많았다. Gemini는 간결성과 형식 준수 측면에서 우수하였으나 일부 확인되지 않은 업무 진행 상태를 기재하였다. GPT-6.2의 분량 및 부가 문단 문제는 향후 항목별 분량 제한과 Few-shot 예시를 통해 개선할 수 있을 것으로 판단된다.

따라서 본 과업의 우선순위와 테스트 결과를 고려할 때 GPT-6.2를 후속 시스템 프롬프트 설계에 활용하는 것이 적절하다는 선정안을 제시한다.

> 제출 전 확인: 미션에서 모델 선정 이유를 학습자가 직접 작성하도록 요구하므로, 위 선정 근거와 점수를 실제 본인의 판단에 맞게 검토·수정하여 확정한다.

## 8. 평가 범위 및 근거 자료

본 비교는 모델별 정상 입력 1회 및 모호한 입력 1회의 결과에 한정되며 모델의 일반적인 성능이나 반복 실행의 일관성을 입증하지 않는다. 유료·무료 환경 차이 또한 통제되지 않았다. 초동 대응 권고는 실제 조치가 수행되었다는 의미가 아니며, 운영 환경에서는 담당자의 검토가 필요하다.

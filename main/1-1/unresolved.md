# 미해결 기록 | IR 서기

> 프롬프트 v2에서도 남은 보고서 품질 문제 및 데이터 한계

## 1. 기록 기준

v1에서 발견된 문제 중 v2에서 해결된 명령어 확인 절차 누락, 차단 효과 단정 및 반복 출력 차이는 이 문서의 미해결 과업으로 집계하지 않는다. 대신 실제 v2 반복 보고서에서 계속 누락된 세부 조사 항목 두 가지를 기록한다. 두 항목은 같은 보고서 입력에서 확인된 서로 다른 출력 목표이다. 항목별로 독립적인 수정 프롬프트를 다시 실행한 기록은 없으므로 추가 재시험을 수행했다고 주장하지 않는다.

## 2. 미해결 과업 01 — 표준 보고서의 취약점/CVE 확인 항목 보존

| 구분 | 내용 |
|---|---|
| 기대 결과 | 미확인 취약점 악용 여부 및 CVE 번호를 표준 보고서의 추가 확인 사항에 명시 |
| 최초 시도 | v1 T5 → T6: 관련 취약점 및 CVE 번호 확인 필요를 명시 |
| 개선 후 시도 | v2 T11 → T12 및 T15 → T16: 두 보고서에서 해당 항목을 독립적으로 명시하지 않음 |
| 최종 상태 | 직접 질의(v2 T13~14)에서는 확인 절차를 제시했으나, 이후 표준 보고서를 다시 생성해도 해당 항목이 복원되지 않음 |

### 시도한 프롬프트 원문

v2 T11 및 T15에 입력한 동일 프롬프트. 전체 시스템 프롬프트는 [시스템 설계 문서 5.2](system-design.md#52-시스템-프롬프트-v2--카테고리-페르소나) 참조.

```text
아래 관제 알람 메모를 바탕으로 초동 대응 보고서 초안을 작성해 줘.\
메모에 없는 내용은 추측하지 말고 '확인 필요'로 남겨 줘.

- 탐지 시각: 2026-11-24 01:42
- 대상 자산(호스트/IP): HOST-ACC-09 / 10.10.4.21
- 관련 계정/프로세스: user_08 / winword.exe → cmd.exe → certutil.exe
- 관제 메모 원문: 회계팀 단말에서 문서 파일 실행 직후 cmd.exe가 certutil.exe를 호출해 외부 IP(198.51.100.77)에서 파일 다운로드를 시도함. EDR이 certutil.exe 프로세스를 즉시 종료해 다운로드는 실패했으나, 최초 실행된 문서 파일의 해시값과 유입 경로(이메일/메신저)는 아직 확인되지 않음.
- 보고 대상: 보안팀장 초동 보고용
```

### 받은 결과 및 막힌 이유 (정리안)

v2는 추가 확인 사항을 4개로 통합하면서 문서의 해시값·악성 여부, 유입 경로, 상세 명령어·다운로드 대상 파일, 피해 범위를 기재하였다. 그러나 취약점 악용 여부와 CVE 번호는 표준 보고서에서 명시되지 않았다. 미확인 값을 만들어내지 않은 점은 적절하지만, 독자가 필요한 조사 항목을 보고서만으로 확인하려면 구체적인 표현이 필요하다. 분량 제한과 조사 항목의 완전성 사이에서 누락이 발생한 것으로 추정된다. 실제 원인은 확인되지 않았다.

**후속 개선 방향(미실행):** 필수 조사 항목의 체크리스트를 두고, 관련성이 있는 취약점 검증 항목을 다른 항목에 묶더라도 명시적으로 포함하도록 한다. 실제 CVE 확정에는 별도의 분석 자료가 필요하다.

## 3. 미해결 과업 02 — 최초 문서 파일 식별 정보의 확인 항목 보존

| 구분 | 내용 |
|---|---|
| 기대 결과 | 최초 문서의 파일명·저장 경로·해시값을 함께 추가 확인 항목에 명시 |
| 최초 시도 | v1 T5/T15 → T6/T16: 파일명, 저장 경로 및 해시값 확인 필요를 명시 |
| 개선 후 시도 | v2 T11/T15 → T12/T16: 해시값·악성 여부를 명시했으나 파일명·저장 경로를 명시하지 않음 |
| 최종 상태 | 두 번의 반복 보고서에서 동일하게 누락됨. 문서 원본의 실제 식별값 역시 입력에 제공되지 않음 |

### 시도한 프롬프트 원문

v2 T15에 재입력한 실제 프롬프트.

```text
아래 관제 알람 메모를 바탕으로 초동 대응 보고서 초안을 작성해 줘.\
메모에 없는 내용은 추측하지 말고 '확인 필요'로 남겨 줘.

- 탐지 시각: 2026-11-24 01:42
- 대상 자산(호스트/IP): HOST-ACC-09 / 10.10.4.21
- 관련 계정/프로세스: user_08 / winword.exe → cmd.exe → certutil.exe
- 관제 메모 원문: 회계팀 단말에서 문서 파일 실행 직후 cmd.exe가 certutil.exe를 호출해 외부 IP(198.51.100.77)에서 파일 다운로드를 시도함. EDR이 certutil.exe 프로세스를 즉시 종료해 다운로드는 실패했으나, 최초 실행된 문서 파일의 해시값과 유입 경로(이메일/메신저)는 아직 확인되지 않음.
- 보고 대상: 보안팀장 초동 보고용
```

### 받은 결과 및 막힌 이유 (정리안)

원본 문서 확보와 해시 산출을 권고하였지만 파일명 및 저장 경로에 대한 명시적 확인 요구가 사라졌다. 다운로드 대상 파일 정보에 대한 확인 항목은 최초 실행 문서의 파일명·저장 경로와 동일하지 않다. 보고서 분량을 줄이기 위해 여러 확인 사항을 묶는 과정에서 세부 식별 항목을 보존하지 못한 것으로 추정된다. 동일 입력을 반복했을 때 출력은 일치하였으나 누락도 반복되었으므로, 출력 일관성 자체가 정보 완전성을 보장하지 않는다는 점을 확인하였다.

**후속 개선 방향(미실행):** 원본 문서의 파일명·경로·해시 등 세부 확인 항목을 하나의 항목으로 묶어서 유지한다. 실제 값은 EDR 기록이나 원본 파일을 확보하기 전까지 확인 필요로 남긴다.

## 4. 추가 데이터 한계 — 모델 오류와 구분

| 확인되지 않은 정보 | 필요한 외부 자료 | 현재 상태 |
|---|---|---|
| 04:15~04:22 사이 실제 실행 명령어 | 셸 이력, auditd, sudo 로그 등 | v2는 적절한 확인 절차를 제공했으나 실제 명령어는 알 수 없음 |
| 사내 유관 부서 보고 기한 | 내부 보안 규정 및 사고 등급별 보고 기준 | 내부 문서 미제공 |
| 문서 해시·유입 경로·CVE | 문서 원본, 전달 기록, 버전·실행 로그 | 원천 증거 미제공 |
| 방화벽 차단의 실제 효과 | 차단 후 통신 기록, 세션 상태 | 효과 미입증 |

위 데이터 한계는 모델이 모르는 정보를 정확히 거부한 경우로, 환각 검증 실패로 분류하지 않는다. v2가 실제 로그를 수집하거나 운영 환경에서 검증했다는 의미도 아니다.

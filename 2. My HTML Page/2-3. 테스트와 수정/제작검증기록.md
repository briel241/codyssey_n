첨부한 `기획서.md`를 읽고, 기획서에 따라 **「알록달록 나의 하루 — 디지털 다이어리」**를 구현해 주세요. 기획서의 **필수 기능, 완료 기준, 한계 및 비목표**를 모두 반영해 주세요.

**구현 요구사항**

- HTML, CSS, JavaScript를 모두 같은 파일에 넣어 브라우저에서 직접 열면 인터넷 연결이나 서버 실행 없이 사용할 수 있게 해 주세요.
- 기기 날짜 기준으로 처음 열었을 때 이번 달과 오늘을 표시해 주세요. 이전 달·다음 달로 이동할 때는 해당 월 1일을 선택하고, 연도 전환과 윤년을 정확히 처리해 주세요. 날짜를 누르면 그 날짜의 본문과 기분을 불러와 주세요.
- 일기 본문이나 기분을 바꾸면 날짜별로 `localStorage`에 자동 저장해 주세요. 하루에 기록은 하나만 유지하고, 본문만 작성하거나 기분만 선택해도 저장되게 해 주세요. 공백만 입력하고 기분을 고르지 않은 경우에는 새 기록을 만들지 말아 주세요. 기존 기록을 이 상태로 비우려고 하면 마지막으로 저장된 기록을 유지하고 삭제 버튼을 사용하라고 안내해 주세요.
- 저장에 성공하면 ‘저장됨’을 표시해 주세요. 저장에 실패하면 ‘저장하지 못했어요’를 표시하고, 입력한 내용은 편집 영역에 남겨 주세요.
- 달력에서 기록이 있는 날짜에는 표시점을, 기분이 저장된 날짜에는 기분 이모지도 표시해 주세요. 삭제는 확인을 거쳐 선택한 날짜에만 적용하고, 취소하면 기록을 유지해 주세요. 기록이 없는 날짜에서는 삭제 버튼을 비활성화해 주세요.
- 밝은 파스텔색, 둥근 모서리, 기본 이모지를 활용해 귀엽고 읽기 쉽게 구성해 주세요. 넓은 화면에서는 달력과 편집 영역을 나란히 배치하고, 좁은 화면에서는 달력 아래에 편집 영역을 배치해 주세요. 화면 폭이 360px일 때도 가로 스크롤 없이 날짜 선택, 본문 입력, 기분 선택, 삭제가 가능해야 합니다. 기분 버튼에는 이모지와 글자를 함께 표시해 주세요.
- 기획서에 없는 기능과 후속 개선 후보인 검색, 월별 기분 요약, 가져오기·내보내기는 이번 구현에서 제외해 주세요. 로그인, API, 서버, AI 기능, 외부 이미지·폰트·라이브러리, 예시 일기도 포함하지 말아 주세요.

## 3. 선택한 결과물과 근거

**선택 결과물 — Codex의 `2-2codex.html`**

- 선택 이유 — 두 결과물 모두 아래 세 가지 실제 테스트에서 요구한 결과를 만족했으므로, 최종 선택에서는 내가 매일 사용하고 싶은 화면인지와 정보를 알아보기 쉬운지를 중요하게 보았다. 그중 Codex의 디자인이 내가 기획한 ‘귀엽고 다채로운 디지털 다이어리’의 분위기에 더 잘 맞아 선택했다.
- 화면 구성 — 크림색 배경 위에 달력과 편집 영역을 나누고, 각 카드 상단에 연보라색과 연분홍색을 사용한 구성이 좋았다. 화면에 여러 색을 사용하면서도 영역별 역할이 구분되어 달력에서 날짜를 고르고 옆에서 일기를 쓰는 흐름을 이해하기 쉽다. 큰 제목과 짧은 소개, 선택 날짜와 요일, 기분 버튼, 본문 입력칸으로 이어지는 배치도 기록에 집중하기에 적절하다고 판단했다.
- 날짜와 기분의 표현 — 선택한 날짜는 보라색 배경과 테두리로 강조하고, 달력 아래 범례에서 오늘·선택일·기록 표시의 의미를 설명하는 점이 마음에 들었다. 기분 버튼마다 서로 다른 파스텔색과 이모지·글자를 함께 사용해 다이어리의 밝은 분위기를 살리면서도 기분을 구분하기 쉽다. 본문 입력칸 아래에 자동 저장과 기분 선택 해제 방법을 안내하는 점도 처음 사용할 때 도움이 된다.
- 최종 판단 — Gemini의 가운데 정렬 제목과 균일한 카드 구성, 날짜 옆 저장 상태 배지도 장점이다. 다만 나는 화면 요소마다 색과 역할이 구분되고, 본문 입력 공간을 필요에 따라 늘릴 수 있는 Codex 쪽이 개인 다이어리로 더 잘 맞는다고 보았다. 따라서 이번 선택은 다른 결과물이 실제 테스트에서 실패했기 때문이 아니라, 두 결과물이 모두 테스트를 만족한 상태에서 디자인과 사용 흐름에 대한 선호를 반영한 것이다.

## 4. 선택한 HTML 테스트 3건

아래 보조 확인은 두 HTML에 같은 모의 실행 조건을 적용한 결과이며, ‘실제 결과’는 작성자가 직접 확인하고 전달한 결과이다. 작성자는 테스트 1·2·3 모두에서 두 결과물이 기준을 만족했다고 확인했다. 보조 확인과 실제 확인에서 차이가 있는 항목은 서로 구분해 기록한다.

### 테스트 1. 월 이동과 윤년 달력 확인

- **테스트 내용** — 처음 화면의 연월과 선택 날짜를 확인한다. 이전·다음 달 버튼으로 2025년 2월과 2024년 2월에 이동해 1일의 요일과 마지막 날짜를 확인한다. 월 이동 직후와 다른 날짜를 누른 직후의 편집 날짜도 확인한다.
- **예상 결과** — 처음에는 기기의 오늘 날짜가 선택된다. 2025년 2월 1일은 토요일이며 28일까지 표시된다. 2024년 2월 1일은 목요일이며 29일까지 표시된다. 월 이동 직후에는 해당 월 1일이 선택된다.
- **실제 결과** — 직접 확인한 결과 Codex와 Gemini 모두 테스트 1의 예상 결과를 만족했다. 처음 화면의 오늘 날짜, 월 이동, 2025년 2월과 2024년 2월의 요일·마지막 날짜, 날짜 선택과 편집 날짜 표시를 확인했으며 두 결과물 모두 만족으로 판단했다.

### 테스트 2. 날짜별 자동 저장, 수정, 삭제 및 복원

- **테스트 내용** — 2024년 2월 28일에 ‘산책을 했다’와 ‘평온해요’, 29일에 ‘영화를 봤다’와 ‘행복해요’를 남긴다. 28일 본문을 ‘저녁에 산책을 했다’로 바꾼다. 29일 삭제를 한 번 한다. 같은 브라우저에서 같은 위치의 파일을 다시 연 뒤 28일과 29일을 확인한다.
- **예상 결과** — 입력한 날짜에 기록 표시가 생긴다. 삭제 취소 시 29일 기록이 남고, 확인 후에는 29일 기록과 표시가 사라진다. 다시 열면 28일의 수정된 본문과 기분만 남는다.
- **실제 결과** — 직접 확인한 결과 Codex와 Gemini 모두 테스트 2의 예상 결과를 만족했다. 날짜별 기록의 자동 저장과 수정, 삭제 취소·확인, 같은 브라우저에서 파일을 다시 열었을 때의 복원을 확인했으며 두 결과물 모두 만족으로 판단했다.

### 테스트 3. 입력값 변경 — 공백만 입력

- **테스트 내용** — 기록이 없는 날짜를 골라 기분을 선택하지 않고 본문에 공백 3칸만 입력한다. 저장 상태와 달력 표시를 확인한 뒤 다른 날짜에 갔다가 돌아온다.
- **예상 결과** — 새 기록이나 달력 표시점이 생기지 않고, 저장 성공으로 표시하지 않는다.
- **실제 결과** — 직접 확인한 결과 Codex와 Gemini 모두 테스트 3의 예상 결과를 만족했다. 기분을 선택하지 않고 공백만 입력했을 때의 기록 생성 여부, 달력 표시와 저장 안내, 다른 날짜로 이동했다 돌아온 뒤의 상태를 확인했으며 두 결과물 모두 만족으로 판단했다. 이는 작성자의 실제 확인 결과이며, 위 모의 환경의 보조 확인 결과와 구분한다.

# 6. 2-3 사용성 개선 기록

개편일: 2026-11-12. 위 1~5절은 2-2 원문을 보존한 이전 미션 기록이다. 과거 작성자가 직접 확인했다고 적은 결과를 이번에 다시 확인한 것으로 간주하지 않는다. 과거 비교표의 모의 실행 결과와 작성자 확인 결과 사이 차이도 원문대로 보존했다.

먼저 날짜를 찾아 일기를 쓰는 흐름의 불편 3건을 대상으로 v2~v4를 개선했다. 저장 데이터 손상 등 내부 기술 문제는 이번 수정 3건에서 제외했다. 아래 ‘AI 요청’은 이번 대화의 요구를 관찰 가능한 현상 중심으로 정리한 요청문이며, 이전에 작성자가 직접 입력했던 문장을 인용한 것은 아니다. 이후 실제 사용자 1명이 준 피드백 3건을 작성자가 전달하여 v5에 반영했다. 사용자 테스트와 반영 결과는 8절과 10절에 기록한다.

## 수정 1 — 다른 달에서 오늘로 돌아오기 (v1 → v2)

- **발견한 문제 / 테스트 내용:** 이전 달 버튼을 6번 눌러 과거 달로 이동한 뒤 오늘 날짜로 돌아갈 방법을 찾는다.
- **예상 결과:** 오늘 날짜를 바로 선택할 수 있다.
- **실제 결과:** v1에는 이전·다음 달 버튼만 있고 오늘 복귀 버튼이 없다. 이번 달로 돌아오려면 다음 달 버튼을 6번 누르고 오늘 날짜를 별도로 선택해야 한다. 화면 구성 및 스크립트 모의 실행으로 확인한 결과이며 실제 참여자의 행동을 관찰한 기록은 아니다.
- **AI 요청:** “지난달 일기를 찾아보고 나서 오늘 일기를 쓰려고 했는데 여러 번 달을 넘겨야 했습니다. 달력 위에 ‘오늘로’ 버튼을 넣어 한 번에 오늘 날짜와 일기를 보여 주세요.”
- **수정 내용:** 달력 위에 ‘오늘로’ 버튼을 추가하고 클릭한 시점의 오늘 날짜, 이번 달, 해당 날짜의 기록을 함께 표시한다.
- **수정 후 테스트 결과:** 자동 보조 검사에서 6개월 전으로 이동 후 버튼을 누르면 오늘 날짜와 연월로 돌아옴을 확인했다. 오늘 기록의 본문·기분 조회와 기존 날짜별 저장·수정·삭제 검사도 통과했다. 실제 브라우저 조작 확인은 아래 수동 검사표에 별도로 기록한다.
- **수정 이유:** 과거 기록을 확인한 뒤 오늘 일기를 쓰는 데 불필요한 반복 조작이 필요하다.

## 수정 2 — 원하는 연도·월로 바로 이동하기 (v2 → v3)

- **발견한 문제 / 테스트 내용:** 2026년 11월에서 2024년 2월 일기를 찾는다.
- **예상 결과:** 원하는 연도와 월을 정해 바로 이동할 수 있다.
- **실제 결과:** v2에서 과거 달로 가는 방법은 한 달씩 넘기는 버튼뿐이다. 위 조건에서는 이전 달 버튼을 33번 눌러야 한다. 이는 이동 규칙을 모의 실행해 계산한 결과이며 실제 참여자의 클릭 횟수를 관찰한 기록은 아니다.
- **AI 요청:** “2024년 2월 일기를 보려는데 한 달씩 여러 번 넘겨야 합니다. 연도와 월을 직접 골라 ‘이동’을 누르면 해당 달이 열리게 해 주세요. 기존 이전·다음 달과 오늘로 버튼도 유지해 주세요.”
- **수정 내용:** 연도 입력칸, 월 선택칸, 이동 버튼을 추가한다. 해당 월 1일을 선택하며 달력과 편집 날짜를 함께 바꾼다. 입력 가능한 연도는 1~9999이며 빈 값·범위 밖 값은 이동하지 않는다.
- **수정 후 테스트 결과:** 2024년 2월로 바로 이동, 윤년 29일 표시, 이전·다음 달 이동 후 입력칸 동기화, 잘못된 연도에서 이동 방지를 자동 보조 검사로 확인했다. ‘오늘로’와 기존 저장·삭제도 다시 확인해 통과했다.
- **수정 이유:** 오래전 기록을 읽거나 테스트 날짜를 찾을 때 반복 클릭이 많아 날짜를 찾기 번거롭다.

## 수정 3 — 노트북 키보드 방향키로 날짜 이동하기 (v3 → v4)

- **발견한 문제 / 테스트 내용:** 달력 날짜를 선택한 뒤 노트북의 ← → ↑ ↓ 키로 옆 날짜와 앞뒤 주의 일기를 살펴보려 한다.
- **예상 결과:** ←/→로 하루씩, ↑/↓로 일주일씩 선택 날짜와 일기 내용이 바뀐다.
- **실제 결과:** v3에는 방향키로 날짜를 바꾸는 처리가 없어 화살표 키를 눌러도 선택 날짜가 바뀌지 않는다. 키 입력 이벤트를 모의 실행해 확인했다. 사용자가 이번 대화에서 이 기능을 요청했다.
- **AI 요청:** “노트북 키보드의 화살표로 날짜를 이동하고 싶습니다. 날짜 버튼에 초점이 있을 때 ←/→는 전날·다음 날, ↑/↓는 7일 전·후로 이동하고 일기 내용도 함께 바꿔 주세요. 월을 넘어가도 계속 이동하고, 본문을 쓰는 중에는 화살표가 글자 커서를 움직이게 해 주세요.”
- **수정 내용:** 날짜 버튼에 한정해 방향키를 처리한다. 월·연도 경계에서도 선택 날짜, 달력, 편집 내용과 초점이 함께 이동한다. Tab으로 달력에 들어오면 선택 날짜부터 시작하며 Tab으로 밖으로 나갈 수 있다. 달력 아래에 조작 안내를 표시한다.
- **수정 후 테스트 결과:** 하루·7일 이동, 2024년 2월 28일→29일→3월 1일, 연도 경계, 이동 후 초점과 날짜별 기록 표시를 자동 보조 검사로 확인했다. 본문에서 발생한 방향키 이벤트가 날짜 이동을 호출하지 않는 것과 기존 오늘 복귀·연월 이동·저장·삭제 동작도 통과했다. 실제 커서·스크롤·키보드 감각은 수동 확인 대상이다.
- **수정 이유:** 여러 날의 일기를 연속해 살펴볼 때 매번 마우스나 터치패드로 날짜를 다시 눌러야 하는 번거로움을 줄인다.

## 8. 실제 사용자 1명 테스트와 피드백 — v5 반영

작성자는 이번 대화에서 v5 변경 사항이 실제 사용자 1명이 준 피드백에 따른 것이라고 확인했다. 이전의 ‘미실시’ 기록을 이 확인에 맞춰 정정한다. 아래 내용은 작성자가 전달한 피드백과 화면 캡처를 근거로 하며, AI가 참여자의 사용 장면을 직접 관찰한 것은 아니다.

- **테스트 참여자:** 사용자 1명. 이름과 관계는 제공되지 않아 익명으로 기록한다.
- **사용한 버전과 작업:** v5 반영 전 v4의 날짜 이동과 기분 선택 화면을 사용·확인하고 의견을 주었다. 참여자에게 제시한 정확한 작업 문구와 사용법 설명 여부는 전달되지 않았다.
- **사용자의 행동과 질문:** 날짜를 이동할 때 선택 블록의 테두리가 겹쳐 보인다는 현상을 보고했다. 전달된 캡처에서도 날짜 18의 테두리가 두 겹으로 보인다. 오늘로 버튼의 위치·색과 기분 선택지에 대한 개선 의견도 주었다. 상세 조작 순서, 멈춘 위치, 별도의 질문은 전달되지 않아 추가로 작성하지 않는다.
- **받은 피드백:** 작성자를 통해 전달된 내용은 ① 날짜 이동 시 선택 블록의 겹친 테두리 수정, ② 오늘로 버튼을 이동 버튼과 같은 줄 맨 오른쪽에 배치하고 색을 다르게 표시, ③ 오늘의 기분을 3개 더 추가해 달라는 요청이다. 참여자의 발언 원문이 아닌 전달된 내용을 요약했다.
- **반영 내용과 결과:** v5에서 날짜 선택·초점을 한 겹 테두리로 표시하고, 오늘로를 연도·월·이동과 같은 줄 오른쪽의 민트색 버튼으로 변경했다. 설레요·피곤해요·불안해요를 추가해 기분을 8개로 늘렸다. 코드 보조 확인에서 날짜 이동·오늘 복귀·기분 저장 및 복원·기존 삭제 기능을 확인했다. 기획서와 README도 v5에 맞춰 갱신했다.
- **반영 후 재테스트:** 작성자는 피드백 반영 후에도 다시 테스트했으며 생각한 대로 잘 동작했다고 확인했다. 이를 바탕으로 요청한 세 가지 개선이 의도에 맞게 반영된 것으로 정리했다. 날짜 이동 시 선택 표시를 선명하게 확인하고, 같은 줄에 모인 이동·오늘로 버튼을 사용하며, 늘어난 기분 선택지를 이용할 수 있도록 개선했다. 이 기록은 작성자가 전달한 재테스트 결과의 요약이며 참여자의 발언을 직접 인용한 것은 아니다. 별도 오류나 추가 수정 요청은 전달되지 않았다.

## 10. 사용자 1명의 피드백 반영 — v4 → v5 (2026-11-12)

이번 변경은 실제 사용자 1명이 준 피드백을 작성자가 이 대화에서 전달한 내용과 화면 캡처에 따라 반영했다. 작성자가 피드백의 출처를 확인하여 기존 기록을 정정했다. AI가 참여자의 사용 과정을 직접 관찰한 것은 아니다. v1~v4와 2-1·2-2 원본은 보존했다.

### 수정 4. 방향키로 이동한 날짜의 테두리 겹침

- **테스트 내용·예상 결과:** 날짜를 선택하고 방향키로 이동하면 선택 날짜의 테두리가 한 겹으로 선명하게 보인다.
- **실제 결과:** 제작자가 제공한 캡처에서 날짜 18의 보라색 테두리가 안쪽과 바깥쪽 두 겹으로 보였다.
- **AI 요청:** “이동할 때 선택되는 블록에서 테두리가 겹칩니다. 겹치지 않게 수정해 주세요.”
- **수정 내용:** 날짜 버튼의 키보드 초점에 별도 바깥 테두리를 추가하는 대신 단일 테두리를 조금 굵게 표시한다. 선택 배경과 키보드 초점 구분은 유지한다.
- **수정 후 테스트 결과:** CSS에서 날짜 초점의 바깥 outline을 제거하고 3px 단일 border로 표시하도록 확인했다. 방향키 날짜·초점 이동의 코드 보조 확인을 통과했다. 작성자의 반영 후 재테스트 성공 확인에 따라, 선택 날짜를 겹친 테두리 없이 구분하려던 개선이 의도대로 반영된 것으로 기록했다.
- **수정 이유:** 두 겹 테두리가 옆 날짜와 맞닿아 보이면 선택 영역이 복잡하고 불안정하게 느껴질 수 있다.

### 수정 5. 오늘로 버튼을 이동 줄 오른쪽으로 배치

- **테스트 내용·예상 결과:** 연도·월·이동·오늘로가 한 줄에 있고 오늘로는 맨 오른쪽에서 색으로 구분된다.
- **실제 결과:** v4에서는 오늘로가 별도 줄에 있고 이동 버튼과 같은 연보라색을 사용했다.
- **AI 요청:** “오늘로 버튼은 색깔을 조금 다르게 하고, 이동 버튼이 있는 줄의 제일 오른쪽에 한 줄로 배치해 주세요.”
- **수정 내용:** 오늘로를 같은 연월 이동 폼 안 마지막 열에 배치하고 민트색으로 변경했다. 일반 버튼으로 유지해 연도 입력이 비어 있어도 오늘로는 바로 작동한다. 좁은 화면에서도 입력칸 너비가 줄어들도록 구성했다.
- **수정 후 테스트 결과:** 폼 안 순서가 연도→월→이동→오늘로인지와 별도 민트색 스타일을 코드로 확인했다. 오늘 복귀·연월 이동의 보조 확인을 통과했다. 작성자의 반영 후 재테스트 성공 확인에 따라, 오늘로 버튼의 위치와 색을 구분하려던 개선이 의도대로 반영된 것으로 기록했다. 정확히 360px에서 수행한 결과는 별도 추가 검사 항목으로 남겼다.
- **수정 이유:** 날짜 이동 조작을 한 곳에서 찾고, 원하는 달로 가기와 오늘로 돌아오기를 쉽게 구분할 수 있다.

### 수정 6. 오늘의 기분 3개 추가

- **테스트 내용·예상 결과:** 기존 5가지 외에도 다양한 감정을 선택하고 날짜별로 다시 읽을 수 있다.
- **실제 결과:** 제공한 화면과 v4에는 행복해요·평온해요·그저 그래요·슬퍼요·화나요 5가지만 있었다.
- **AI 요청:** “오늘의 기분을 3개 더 늘려 주세요.”
- **수정 내용:** 설레요(🤩), 피곤해요(😴), 불안해요(😟)를 더해 총 8개로 만들었다. 이모지·글자·파스텔 배경을 적용했다. 하루에 한 기분 선택, 재클릭 해제 규칙은 유지했다.
- **수정 후 테스트 결과:** 총 8개 생성, 새 기분 3개의 단일 선택·해제·날짜별 저장·복원·달력 이모지와 삭제, 기존 기분 동작의 코드 보조 확인을 통과했다. 작성자는 반영 후 재테스트도 의도대로 동작했다고 확인했다. 이에 따라 선택 가능한 감정을 늘리려던 개선이 의도에 맞게 반영된 것으로 기록했다.
- **수정 이유:** 설렘·피로·불안을 기존 5개 중 하나로 바꿔 적어야 하는 불편을 줄인다.

### v5 추가 확인에 사용할 항목

- 날짜를 클릭한 뒤 ←/→/↑/↓로 이동하고 테두리가 한 겹인지 확인한다.
- 360px와 노트북 화면에서 연도·월·이동·오늘로가 한 줄이며 오늘로가 오른쪽에 있는지 확인한다.
- 연도 입력을 비우고 오늘로를 눌러도 오늘로 돌아오는지 확인한다.
- 새 기분 3개를 서로 다른 날짜에 저장한 뒤 날짜 이동·새로고침으로 복원되는지 확인한다.
- 기존 본문 입력·기분 변경·삭제 취소/확인·월 경계 방향키 이동도 확인한다.

검사 스크립트 파일은 제출 폴더에 추가하지 않았다. 사용자 1명의 피드백 3건을 v5에 반영했고, 작성자가 반영 후 재테스트도 의도대로 잘 동작했다고 확인했다. 피드백에서 발견한 불편을 수정하고 결과를 다시 확인하는 개선 과정을 기록했다. 정확한 화면 폭 등 개별 검사 조건이나 참여자의 발언은 전달받은 범위를 넘어 작성하지 않았다.

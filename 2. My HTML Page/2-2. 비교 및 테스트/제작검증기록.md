첨부한 `기획서.md`를 읽고, 기획서에 따라 **「알록달록 나의 하루 — 디지털 다이어리」**를 구현해 주세요. 기획서의 **필수 기능, 완료 기준, 한계 및 비목표**를 모두 반영해 주세요.

**구현 요구사항**

- HTML, CSS, JavaScript를 모두 같은 파일에 넣어 브라우저에서 직접 열면 인터넷 연결이나 서버 실행 없이 사용할 수 있게 해 주세요.
- 기기 날짜 기준으로 처음 열었을 때 이번 달과 오늘을 표시해 주세요. 이전 달·다음 달로 이동할 때는 해당 월 1일을 선택하고, 연도 전환과 윤년을 정확히 처리해 주세요. 날짜를 누르면 그 날짜의 본문과 기분을 불러와 주세요.
- 일기 본문이나 기분을 바꾸면 날짜별로 `localStorage`에 자동 저장해 주세요. 하루에 기록은 하나만 유지하고, 본문만 작성하거나 기분만 선택해도 저장되게 해 주세요. 공백만 입력하고 기분을 고르지 않은 경우에는 새 기록을 만들지 말아 주세요. 기존 기록을 이 상태로 비우려고 하면 마지막으로 저장된 기록을 유지하고 삭제 버튼을 사용하라고 안내해 주세요.
- 저장에 성공하면 ‘저장됨’을 표시해 주세요. 저장에 실패하면 ‘저장하지 못했어요’를 표시하고, 입력한 내용은 편집 영역에 남겨 주세요.
- 달력에서 기록이 있는 날짜에는 표시점을, 기분이 저장된 날짜에는 기분 이모지도 표시해 주세요. 삭제는 확인을 거쳐 선택한 날짜에만 적용하고, 취소하면 기록을 유지해 주세요. 기록이 없는 날짜에서는 삭제 버튼을 비활성화해 주세요.
- 밝은 파스텔색, 둥근 모서리, 기본 이모지를 활용해 귀엽고 읽기 쉽게 구성해 주세요. 넓은 화면에서는 달력과 편집 영역을 나란히 배치하고, 좁은 화면에서는 달력 아래에 편집 영역을 배치해 주세요. 화면 폭이 360px일 때도 가로 스크롤 없이 날짜 선택, 본문 입력, 기분 선택, 삭제가 가능해야 합니다. 기분 버튼에는 이모지와 글자를 함께 표시해 주세요.
- 기획서에 없는 기능과 후속 개선 후보인 검색, 월별 기분 요약, 가져오기·내보내기는 이번 구현에서 제외해 주세요. 로그인, API, 서버, AI 기능, 외부 이미지·폰트·라이브러리, 예시 일기도 포함하지 말아 주세요.

## 3. 선택한 결과물과 근거

**선택 결과물 — Codex의 `2-2codex.html`**

- 선택 이유 — 두 결과물 모두 아래 세 가지 실제 테스트에서 요구한 결과를 만족했으므로, 최종 선택에서는 내가 매일 사용하고 싶은 화면인지와 정보를 알아보기 쉬운지를 중요하게 보았다. 그중 Codex의 디자인이 내가 기획한 ‘귀엽고 다채로운 디지털 다이어리’의 분위기에 더 잘 맞아 선택했다.
- 화면 구성 — 크림색 배경 위에 달력과 편집 영역을 나누고, 각 카드 상단에 연보라색과 연분홍색을 사용한 구성이 좋았다. 화면에 여러 색을 사용하면서도 영역별 역할이 구분되어 달력에서 날짜를 고르고 옆에서 일기를 쓰는 흐름을 이해하기 쉽다. 큰 제목과 짧은 소개, 선택 날짜와 요일, 기분 버튼, 본문 입력칸으로 이어지는 배치도 기록에 집중하기에 적절하다고 판단했다.
- 날짜와 기분의 표현 — 선택한 날짜는 보라색 배경과 테두리로 강조하고, 달력 아래 범례에서 오늘·선택일·기록 표시의 의미를 설명하는 점이 마음에 들었다. 기분 버튼마다 서로 다른 파스텔색과 이모지·글자를 함께 사용해 다이어리의 밝은 분위기를 살리면서도 기분을 구분하기 쉽다. 본문 입력칸 아래에 자동 저장과 기분 선택 해제 방법을 안내하는 점도 처음 사용할 때 도움이 된다.
- 최종 판단 — Gemini의 가운데 정렬 제목과 균일한 카드 구성, 날짜 옆 저장 상태 배지도 장점이다. 다만 나는 화면 요소마다 색과 역할이 구분되고, 본문 입력 공간을 필요에 따라 늘릴 수 있는 Codex 쪽이 개인 다이어리로 더 잘 맞는다고 보았다. 따라서 이번 선택은 다른 결과물이 실제 테스트에서 실패했기 때문이 아니라, 두 결과물이 모두 테스트를 만족한 상태에서 디자인과 사용 흐름에 대한 선호를 반영한 것이다.

## 4. 선택한 HTML 테스트 3건

아래 보조 확인은 두 HTML에 같은 모의 실행 조건을 적용한 결과이며, ‘실제 결과’는 작성자가 직접 확인하고 전달한 결과이다. 작성자는 테스트 1·2·3 모두에서 두 결과물이 기준을 만족했다고 확인했다. 보조 확인과 실제 확인에서 차이가 있는 항목은 서로 구분해 기록한다.

### 테스트 1. 월 이동과 윤년 달력 확인

- **테스트 내용** — 처음 화면의 연월과 선택 날짜를 확인한다. 이전·다음 달 버튼으로 2025년 2월과 2024년 2월에 이동해 1일의 요일과 마지막 날짜를 확인한다. 월 이동 직후와 다른 날짜를 누른 직후의 편집 날짜도 확인한다.
- **예상 결과** — 처음에는 기기의 오늘 날짜가 선택된다. 2025년 2월 1일은 토요일이며 28일까지 표시된다. 2024년 2월 1일은 목요일이며 29일까지 표시된다. 월 이동 직후에는 해당 월 1일이 선택된다.
- **실제 결과** — 직접 확인한 결과 Codex와 Gemini 모두 테스트 1의 예상 결과를 만족했다. 처음 화면의 오늘 날짜, 월 이동, 2025년 2월과 2024년 2월의 요일·마지막 날짜, 날짜 선택과 편집 날짜 표시를 확인했으며 두 결과물 모두 만족으로 판단했다.

### 테스트 2. 날짜별 자동 저장, 수정, 삭제 및 복원

- **테스트 내용** — 2024년 2월 28일에 ‘산책을 했다’와 ‘평온해요’, 29일에 ‘영화를 봤다’와 ‘행복해요’를 남긴다. 28일 본문을 ‘저녁에 산책을 했다’로 바꾼다. 29일 삭제를 한 번 한다. 같은 브라우저에서 같은 위치의 파일을 다시 연 뒤 28일과 29일을 확인한다.
- **예상 결과** — 입력한 날짜에 기록 표시가 생긴다. 삭제 취소 시 29일 기록이 남고, 확인 후에는 29일 기록과 표시가 사라진다. 다시 열면 28일의 수정된 본문과 기분만 남는다.
- **실제 결과** — 직접 확인한 결과 Codex와 Gemini 모두 테스트 2의 예상 결과를 만족했다. 날짜별 기록의 자동 저장과 수정, 삭제 취소·확인, 같은 브라우저에서 파일을 다시 열었을 때의 복원을 확인했으며 두 결과물 모두 만족으로 판단했다.

### 테스트 3. 입력값 변경 — 공백만 입력

- **테스트 내용** — 기록이 없는 날짜를 골라 기분을 선택하지 않고 본문에 공백 3칸만 입력한다. 저장 상태와 달력 표시를 확인한 뒤 다른 날짜에 갔다가 돌아온다.
- **예상 결과** — 새 기록이나 달력 표시점이 생기지 않고, 저장 성공으로 표시하지 않는다.
- **실제 결과** — 직접 확인한 결과 Codex와 Gemini 모두 테스트 3의 예상 결과를 만족했다. 기분을 선택하지 않고 공백만 입력했을 때의 기록 생성 여부, 달력 표시와 저장 안내, 다른 날짜로 이동했다 돌아온 뒤의 상태를 확인했으며 두 결과물 모두 만족으로 판단했다. 이는 작성자의 실제 확인 결과이며, 위 모의 환경의 보조 확인 결과와 구분한다.

## 2. 좁혀서 적은 한 문장

**새 영화를 추가할 수 없고 영화 수에 따라 보관함이 길어지거나 작아지는 문제를, 영화 입력 기능과 6편 단위 탐색·고정 크기 보관함으로 개선한다.**

처음에는 **새 영화를 추가할 수 없는 기능의 부족**에 집중했다. 이후 화면을 사용하며 드러난 탐색 방식, 불필요한 안내, 하단 정렬, 보관함 크기 변화도 각각 나누어 수정했다.

## 4. AI가 말한 원인과, 그 설명을 직접 확인한 결과

### 영화 추가와 개수 표시

AI는 영화 데이터가 기본 배열에만 들어 있고, 새 영화 정보를 입력받아 목록에 추가하는 처리가 없다고 설명했다. 원본 코드에서 기본 영화 8편이 들어 있는 `movies` 배열과 영화 추가용 입력창이 없는 구성을 확인했다. 보관함 개수와 저장 안내에도 `8-count`, `n<8`, `8-n`처럼 고정된 값이 있었다.

수정본에는 영화 추가 폼을 만들고, 개수 계산 기준을 `movies.length`로 바꿨다. 추가한 영화와 등급 배치는 브라우저 저장소에 보관하도록 했다.

### 보관함 탐색과 페이지 이동

기존 보관함은 영화 수에 따라 행이 늘어나는 구조였다. 이를 **2열 × 3행**으로 바꾸고, 7번째 영화부터는 오른쪽에 이어 배치했다. 나머지 영화는 삭제하지 않고 좌우로 이동해 볼 수 있도록 했다.

버튼 이동은 현재 스크롤 위치에 조금씩 이동량을 더하는 방식 대신, **앞·뒤 페이지의 시작 위치로 즉시 이동**하도록 고쳤다. 스크롤 이벤트마다 위치를 다시 대입하던 처리도 정리했다.

### 보관함 위치와 크기

화면 캡처와 사용자 피드백을 통해 보드와 보관함의 하단 높이가 다르고, 영화를 옮기면 보관함이 작아지는 현상을 확인했다. 코드에서는 카드 행 높이가 내용에 따라 달라지는 점을 확인했다.

최종적으로 보관함을 하단에 맞춰 배치하고, 카드 영역은 **170px 높이의 3개 행과 간격·여백을 포함한 558px**로 고정했다. 따라서 영화가 일부 남거나 모두 이동해도 같은 공간을 유지한다.

## 6. 최종 화면 구성

- **소개 영역:** “좋아하는 영화를 더하는 나만의 취향”, “나의 영화 등급표”와 기존 소개 문구를 유지한다.
- **취향 보드:** S·A·B·C 등급에 영화를 배치한다.
- **영화 보관함:** 한 번에 최대 6편을 표시하고, 나머지는 오른쪽 페이지에서 확인한다.
- **탐색:** 좌우 버튼으로 한 페이지씩 넘긴다. 모바일 스와이프와 보관함 빈 영역의 마우스 드래그도 지원한다.
- **배치:** 넓은 화면에서는 보관함 아래 테두리와 C등급 칸 아래 테두리를 맞춘다.
- **크기:** 보관함이 비어도 카드 6편을 표시할 공간을 유지한다.
- **안내:** 긴 사용 설명과 불필요한 드래그 손잡이는 표시하지 않는다.

## 7. 실제 브라우저 최종 확인 목록

- [ ] 새 영화의 제목·개봉 연도·장르를 입력해 보관함에 추가한다.
- [ ] 빈 제목, 잘못된 연도, 장르 미선택과 중복 등록이 처리되는지 확인한다.
- [ ] 좌우 버튼으로 6편씩 넘기고 첫·마지막 페이지에서 더 넘어가지 않는지 확인한다.
- [ ] 새 영화도 클릭하거나 드래그해 원하는 등급으로 옮긴다.
- [ ] 영화를 모두 옮겨도 보관함 크기가 유지되는지 확인한다.
- [ ] 보관함과 C등급 칸의 아래 테두리가 같은 높이인지 확인한다.
- [ ] 새로고침한 뒤 추가 영화와 등급 배치가 복원되는지 확인한다.
- [ ] 좁은 화면에서 보관함 배치와 좌우 스와이프를 확인한다.

## 8. 이번 수정에서 배운 점

새로운 버튼을 만드는 것만으로 작업이 끝나는 것은 아니었다. 영화가 늘어나면 개수 표시와 저장 방식도 바뀌어야 했고, 실제로 사용할 때는 탐색 방식과 화면의 크기 변화까지 영향을 주었다.

특히 **영화가 없는 상태도 하나의 정상적인 화면**이라는 점을 배웠다. 보관함에 카드가 많을 때뿐 아니라 1편만 남았을 때와 모두 옮겼을 때도 같은 기준으로 확인해야 했다.

앞으로도 문제를 한 문장으로 좁히고, **행동 재현 → 원인 확인 → 필요한 부분 수정 → 같은 행동으로 다시 확인**하는 순서로 작업하고자 한다.

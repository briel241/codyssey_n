## 2. AI가 물어서 내가 정한 것

웹앱을 만들기 전에 AI가 여러 가지 선택지를 질문했고, 나는 다음과 같이 결정했다.

- 결과물 형식은 브라우저에서 바로 열 수 있는 **HTML 단일 파일**로 정했다.
- HTML, CSS, JavaScript가 모두 한 파일 안에 들어가도록 했다.
- 별도의 서버, API, 외부 파일 없이 실행되도록 정했다.
- 영화 등급은 **S, A, B, C** 네 단계로 나누기로 했다.
- 사용자가 영화를 직접 옮길 수 있도록 **드래그 앤 드롭 방식**을 선택했다.
- 전체적인 디자인은 깔끔하고 현대적인 느낌의 **토스 스타일 UI**를 참고하도록 했다.
- 등급표를 저장할 때는 **닉네임 또는 익명**으로 저장할 수 있게 정했다.
- 저장된 등급표 목록과 영화별 인기도를 함께 볼 수 있도록 구성했다.
- 영화 포스터는 API를 사용하지 않고, 로컬 또는 직접 입력한 이미지 주소를 활용하는 방식으로 정했다.

## 3. 같은 행동으로 비교한 결과

### 해본 행동
같은 요구사항을 gpt와 gemini에 각각 입력하여 영화 등급 분류 웹앱을 만들도록 했다.  
두 AI 모두에게 HTML, CSS, JavaScript가 포함된 단일 HTML 파일을 만들어 달라고 요청했고, 결과물의 구성과 디자인, 완성도를 비교했다.

### 기대 결과
처음에는 gpt가 유료 모델이고 전반적인 코드 작성 능력과 디자인 완성도가 더 높을 것이라고 예상했다.  
특히 단순히 기능만 구현하는 것이 아니라, 사용자가 보기 편한 화면 구성과 세부적인 CSS 디자인까지 더 자연스럽게 만들어 줄 것이라고 기대했다.

### AI A(gpt)의 결과
gpt는 전체적인 화면 구성이 더 깔끔했고, 디자인이 더 완성도 있게 느껴졌다.  
등급표 영역, 저장 영역, 버튼, 안내 문구 등이 보기 좋게 배치되었고, CSS도 세부적으로 정리되어 있어 실제 웹앱처럼 보였다.  
또한 사용자가 드래그 앤 드롭으로 영화를 옮기고 저장하는 흐름이 비교적 자연스럽게 구성되어 있었다.

### AI B(gemini)의 결과
gemini도 기본적인 기능 구현은 가능했지만, 전체적인 디자인의 완성도나 세부적인 화면 구성 면에서는 gpt보다 조금 아쉬웠다.  
기능 자체는 이해할 수 있었지만, 시각적으로 끌리는 정도나 CSS의 디테일에서는 gpt 결과물이 더 좋다고 느꼈다.

### 비교 결과 정리
같은 요구사항으로 비교했을 때, gpt가 만든 결과물이 디자인과 세부 구성 면에서 더 우수했다.  
특히 CSS 스타일, 화면 배치, 사용자 경험 측면에서 gpt의 결과물이 더 자연스럽고 보기 좋았다.  
따라서 이번 미션에서는 AI A인 gpt의 결과물을 선택했다.

## 5. 선택한 이유

AI A인 gpt의 결과물이 전체적으로 더 예쁘고 완성도가 높게 느껴졌기 때문에 선택했다.  
단순히 기능만 구현된 것이 아니라, 화면의 분위기와 구성, 버튼 스타일, 등급표 배치 등이 더 깔끔하게 정리되어 있었다.  
사용자가 실제로 사용해 보고 싶다는 느낌이 들 정도로 시각적인 완성도가 높았고, 내가 원했던 웹앱의 이미지와도 더 잘 맞았다.

## 7. 수정하지 않은 이유

gpt가 만들어 준 결과물이 내가 기대했던 방향과 충분히 잘 맞았기 때문에 따로 수정하지 않았다.  
기능 구성과 디자인이 모두 만족스러웠고, 처음에 생각했던 영화 등급 분류 웹앱의 모습이 잘 표현되어 있었다.  
따라서 추가 수정 없이 그대로 사용해도 괜찮다고 판단했다.
